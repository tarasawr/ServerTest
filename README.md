# esp-server

Мост между платой ESP8266 и приложением на Unity.

```
ESP8266  --POST /api/sensors-->  esp-server  --WebSocket /ws-->  Unity
                                     |
                                     └─ пока плата молчит, показания генерирует симулятор
```

Пока прошивки нет, сервер сам выдаёт правдоподобные данные, так что Unity можно доделывать
без единого провода. Как только реальная плата начнёт слать POST — она автоматически перехватывает
управление, никаких флагов переключать не нужно.

## Запуск локально

```bash
npm install
npm start          # http://localhost:3000
```

Открой `http://localhost:3000` в браузере — там дашборд, по которому сразу видно, живой ли сервер.
Проверка сокета из консоли: `node smoke.js`.

## API

| Метод | Путь | Кто ходит | Зачем |
|---|---|---|---|
| WS | `/ws` | Unity | снапшот сразу после подключения и дальше раз в тик |
| GET | `/api/sensors` | кто угодно | тот же снапшот, разово |
| GET | `/api/history` | Unity, графики | последний час: `?ids=a,b` обрезает до нужных рядов |
| POST | `/api/sensors` | ESP8266 | прислать показания |
| GET | `/health` | Render | проверка живости |

### Формат снапшота

```json
{
  "type": "snapshot",
  "deviceId": "esp8266-sim",
  "source": "fake",
  "online": false,
  "ts": 1786213938744,
  "serverTs": 1786213938744,
  "deviceTs": 0,
  "uptimeSec": 1,
  "rssi": -58,
  "device": {},
  "sensors": [
    { "id": "temperature1", "label": "Температура 1", "unit": "°C",
      "kind": "number", "min": -20, "max": 60, "decimals": 1, "value": 23.1 }
  ]
}
```

`source` — откуда цифры: `device` (реальная плата) или `fake` (симулятор).
Массив, а не объект, специально: Unity `JsonUtility` не умеет словари, зато отлично разбирает
массивы, и UI строится прямо по нему.

Времени в снапшоте три поля, и это не дублирование:

| Поле | Что это |
|---|---|
| `deviceTs` | часы самой платы (NTP, UTC мс). `0` — плата молчит или её время не синхронизировано |
| `serverTs` | часы сервера в момент отправки. По разнице с `deviceTs` видно расхождение |
| `ts` | чем подписан замер: `deviceTs`, когда он есть, иначе `serverTs` |

По `ts` Unity рисует ось графика, поэтому там должно стоять время того, кто мерил, а не время,
когда пакет доехал. Плата отчитывается раз в 10 с, а снапшоты уходят каждую секунду — между
отчётами `deviceTs` досчитывается по серверным часам, иначе время в интерфейсе дёргалось бы
рывками. Метку, разошедшуюся с серверной больше чем на `DEVICE_CLOCK_TOLERANCE_MS`, сервер
отбрасывает и один раз ругается в лог: криво выставленные часы платы иначе утащили бы весь
график в другой год.

### Формат истории

```json
{
  "type": "history",
  "windowSec": 3600,
  "everySec": 10,
  "ts": [1786216231076, 1786216241076],
  "series": [
    { "id": "temperature1", "label": "Температура 1", "unit": "°C",
      "decimals": 1, "values": [23.1, 23.3] }
  ]
}
```

Метки времени общие для всех рядов — замеры берутся одновременно, дублировать их в каждом ряду
незачем. Значения плоскими массивами: вдвое меньше байт, чем массив объектов, и `JsonUtility` их
разбирает. `ts` не влезает в 32 бита, на стороне Unity это `long[]`.

График в Unity работает в два этапа: один запрос сюда при старте даёт прошлое, дальше точки
добавляются из живых снапшотов — но не чаще `everySec`, иначе шаг по оси времени поехал бы.
Окно графика Unity держит своё (по умолчанию три часа) и шире серверного: чего история не
покрыла, то дорисуется живыми точками по мере работы.

**История при старте засеяна.** Сервер живёт только между засыпаниями Render, и без засева
каждый запуск Unity встречал бы пустой график. Поэтому на старте окно заполняется тем же
случайным блужданием, что и симулятор, только развёрнутым назад во времени, — в логе это
видно строкой `history seeded with 360 simulated point(s)`. Это имитация, а не измерения:
`HISTORY_SEED=0` выключает засев, и график начинает копиться с нуля.

### Что шлёт плата

Плоский объект — так проще всего собрать на ESP8266:

```bash
curl -X POST http://localhost:3000/api/sensors \
  -H 'Content-Type: application/json' \
  -d '{"deviceId":"esp8266-kitchen","rssi":-61,"ts":1786453454395,"temperature1":23.4,"temperature2":25.1,"humidity":48.2,"motion":true}'
```

Незнакомые поля просто игнорируются, так что прошивка может слать не все датчики сразу.
`ts` — необязательное время замера по часам платы (UTC, мс); без него замер подписывается
серверным временем.

### Паспорт платы

Необязательный объект `device` рядом с показаниями — всё, что плата знает про себя. Сервер его
не разбирает по полям: что прошивка положила, то и уедет в снапшот, а Unity разложит по строкам.
Добавить в статус, скажем, напряжение питания — это правка одной прошивки, ни сервер, ни C#
трогать не нужно.

```json
{
  "deviceId": "esp8266-kitchen", "rssi": -61,
  "temperature1": 23.4, "temperature2": 25.1,
  "device": {
    "board": "NodeMCU ESP8266 (ESP-12E) + OLED 0.96\"", "fw": "1.0.0",
    "ip": "192.168.0.14", "mac": "5C:CF:7F:11:22:33",
    "ssid": "MyHomeWiFi", "bssid": "aa:bb:cc:dd:ee:ff", "channel": 6,
    "chipId": "00A1B2", "cpuMhz": 80, "flashKB": 4096, "sketchKB": 377,
    "freeHeapB": 29112, "uptimeSec": 7983, "reset": "External System",
    "sensorsFound": 2, "oneWirePin": 13, "oled": "SDA12/SCL14 0x3C",
    "sent": 812, "failed": 1, "intervalSec": 10
  }
}
```

Пропускаются только плоские скаляры (строка / число / bool): вложенные объекты и массивы
`JsonUtility` в Unity всё равно не разберёт. Не больше 32 полей, строки режутся до 96 символов —
чтобы одно кривое значение не раздуло снапшот, который уходит всем клиентам раз в секунду.
Пока плата не на связи, в снапшоте лежит пустой `device: {}`, а не `null`: клиенту так не нужно
проверять на null перед каждым полем.

## Датчики

Список живёт в `src/catalog.js` и едет внутри каждого снапшота вместе с подписями, единицами и
границами шкалы. **Добавить датчик = добавить строку в `CATALOG`** — на сервере и в браузерном
дашборде он появится сам.

В Unity верстка своя, поэтому там датчик нужно ещё привязать к тексту: в инспекторе `UiController`
поля `Temp1 Sensor Id` / `Temp2 Sensor Id` задают, чей `id` попадёт в какой `TextMeshProUGUI`.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `3000` | на Render проставляется сам |
| `DEVICE_KEY` | пусто | секрет в заголовке `X-Device-Key`. Пусто = POST принимается от кого угодно |
| `DEVICE_TIMEOUT_MS` | `15000` | молчание дольше этого — плата считается ушедшей, симулятор возвращается |
| `TICK_MS` | `1000` | как часто генерируется и рассылается снапшот |
| `HISTORY_WINDOW_MS` | `3600000` | сколько времени держим историю (час) |
| `HISTORY_EVERY_MS` | `10000` | шаг между точками графика. Мельче `TICK_MS` не станет — историю пишет тик, сервер об этом предупредит на старте |
| `HISTORY_SEED` | `1` | заполнить окно истории имитацией при старте. `0` — начинать с пустого графика |
| `DEVICE_CLOCK_TOLERANCE_MS` | `300000` | насколько часам платы позволено разойтись с серверными, прежде чем её `ts` перестанут принимать |
| `STATUS_EVERY_MS` | `60000` | как часто в лог падает строка `Status` со сводкой |

## Деплой на Render

Web Service, Node, `npm install` / `npm start`, health check `/health`. Порт брать из `PORT`.
WebSocket на бесплатном тарифе работает, но инстанс засыпает после 15 минут без трафика
(холодный старт ~50 с). Плата, шлющая данные раз в 10–30 секунд, держит его в тонусе постоянно;
клиент Unity в любом случае переподключается сам.

Обязательно выставь `DEVICE_KEY` в проде — иначе показания сможет подделать кто угодно.
